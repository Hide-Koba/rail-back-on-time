## 0. 実装者への指示（最初に読むこと）

1. **§9 のマイルストーン順に実装する。** 各マイルストーンの受け入れ条件（テストを含む）を満たしてから次へ進む。
2. **シミュレーションはDOMに依存しない純粋なモジュールにする**（`src/sim/` 以下）。描画（`src/render/`）はシミュレーションの状態を読むだけにする。こうしておけば Node でテストでき、自動運転のベースラインも画面なしで計算できる。
3. **外部ライブラリやビルドツールは使わない。** HTML + CSS + ES Modules（素のJavaScript）で書き、テストは Node 標準の `node:test` を使う。
4. **乱数は使わない**（M4 のイベントで使う場合はシード付きの疑似乱数にする）。同じ入力からは必ず同じ結果になるようにする。
5. 数値（速度・時間・駅の配置・列車表）は `src/config.js` と `src/stages/*.js` にまとめる。調整で本書と違う値にしたときは、本書の該当表も更新する。
6. 実在の鉄道会社のロゴ・社名・列車愛称（のぞみ、ひかり、こだま 等）・画面デザインそのものは使わない。駅名・種別名はすべて架空にする（§4）。
7. 本書で決まっていない細部は、「プレイヤーにとって分かりやすい方」「実装が単純な方」の順で判断する。判断した内容は `docs/DECISIONS.md` に1行ずつ書き残す。

## 1. コンセプト

### 1.1 一言で

> 遅延で団子になった新幹線を、待避と発車順の入れ替えでさばき、乗客の遅れを最小にする「運転指令」パズル。

### 1.2 元ネタと面白さの核

実際の遅延時の列車走行位置画面では、遅れた列車が終点の手前まで数珠つなぎになる。原因は次の2つ。

- **追い越しは駅でしかできない。** 遅い各停が前にいると、後ろの速達はつかえる。
- **終点のホームが足りない。** 折り返しに時間がかかり、ホームが空かないと次の列車が入れない。

プレイヤーは指令員として、**駅でどの列車を待たせて、どの列車を先に通すか**を決める。全員を同時に救うことはできない（各停を待たせれば、その各停はさらに遅れる）。このトレードオフが遊びの中心になる。

### 1.3 試作で検証したいこと

- 進路切り替えと抑止の2つの操作だけで、判断する面白さが出るか
- 自動運転より上手くさばけたときに手応えがあるか（スコアで分かるか）
- スマホの縦画面で操作できるか

### 1.4 試作でやらないこと

- 上り方向（試作は下り方向の片側だけ）
- 列車の長さ、加減速の物理計算（§3 の簡略モデルで代用）
- サウンド、BGM
- アカウント、ランキング、ネット通信

## 2. 用語

| 用語 | 意味（本書での定義） |
|---|---|
| 本線 | 駅を通過する列車が通る線路。ホームがない場合がある |
| 副本線（待避線） | 本線の横にある線路。ホームがあり、停車する列車や追い越される列車が入る |
| 進路 | 列車が駅に入るときに使う番線。ポイント（分岐器）で決まる |
| 進路確定 | 列車が駅に近づき、進路を変えられなくなった状態 |
| 抑止 | 列車を駅に止めたまま発車させないこと |
| 運転停車 | 本来は通過する駅に、待避などのために止まること（客扱いはしない） |
| 閉そく（ブロック） | 線路を区切った単位。1つのブロックには1本の列車しか入れない |
| 遅延 | 実際の時刻 − 定刻（秒）。画面には分で表示する |
| 遅延損失 | Σ（列車の終点到着遅延[分] × 乗客数）。単位は「人分」。スコアに使う |
| ベースライン | プレイヤーが何も操作しなかった場合（自動運転）の遅延損失 |

## 3. シミュレーション仕様

### 3.1 時間

- 1ティック = ゲーム内1秒（`DT_SEC = 1`）の固定刻みで進める。
- 実時間との換算: 等速（1x）で **実時間1秒 = ゲーム内20秒**。2x = 40秒、4x = 80秒。一時停止もできる。
- 描画は `requestAnimationFrame` で行う。前フレームからの実時間 × 倍率ぶんのティックを、まとめて `step()` する。1フレームあたりの上限は 400 ティックとする。
- ゲーム内時刻は秒の整数で持ち、表示するときに `HH:MM` に変換する。

### 3.2 路線の構造

路線は、上（上流 = 東京方面）から下（終点）へ向かう1本の線。位置は km（実数）で表す。

```
[入線点 entryKm] ── 区間0 ── [駅0] ── 区間1 ── [駅1] ── … ── [終点駅]
```

- **駅**は中心位置 `km` を持ち、`km ± STATION_HALF_KM`（0.5 km）の範囲を占める。
- **区間**は、隣り合う駅の端から端まで（最初の区間は入線点から駅0の上端まで）。
- 各区間は長さを `BLOCK_KM`（3.0 km）でおおよそ均等に割り、`ceil(長さ / BLOCK_KM)` 個のブロックに分ける。
- 駅の各番線は、それぞれ1つのリソース（ブロックと同じく1本しか入れない）。
- 駅を出るとき、どの番線からでも次の区間の最初のブロックへ合流する。

### 3.3 リソースの占有ルール（衝突防止）

- 列車は先頭の位置だけで表す（長さは無視する）。先頭がいるリソース（ブロックまたは番線）を1つだけ占有する。
- 次のリソースへ入るには、そのリソースが空いていることが必要。入った瞬間に占有し、前のリソースを解放する。
- **不変条件:** どのティックでも、1つのリソースを2本以上の列車が占有してはならない。テストで全ティックを検査する（§10）。

### 3.4 1ティックの処理順

`step(state, commands)` は次の順に処理する。

1. 入力コマンドを適用する（§3.10）。
2. 入線処理: 入線時刻を過ぎて待っている列車を、入線順（実際の入線時刻、同じなら列車ID順）に、最初のブロックが空いていれば入線させる。空いていなければ待機列に残す。
3. 列車を **km の大きい順**（前にいる順）に1本ずつ処理する。km が同じ場合は「本線にいる列車」を先に処理する。各列車について:
   - 速度を決める（§3.6）
   - 進路を確定させる（§3.7）
   - 移動するか、停車・待機を続ける（§3.5）
4. 時刻を `DT_SEC` 進める。
5. 終了判定（§3.11）。

前の列車から処理するので、前の列車がリソースを空けた同じティックに、後ろの列車がそこへ入れる。

### 3.5 列車の状態と遷移

| 状態 | 意味 |
|---|---|
| `queued` | 入線待ち（画面外の待機列） |
| `running` | 走行中 |
| `signal` | 信号待ち。次のリソースがふさがっているため、境界で停止中 |
| `dwelling` | 駅で停車中（客扱い、または運転停車） |
| `turnaround` | 終点で折り返し準備中（ホームを占有中） |
| `done` | 終了。盤面から消す |

**走行（`running`）**
- 1ティックで `速度[km/h] × DT_SEC / 3600` km 進む。
- 現在のリソースの終わりを超えるとき、次のリソースが空いていれば入り、余った距離をそのまま進む。ふさがっていれば境界で止まり、`signal` になる。
- 停車する駅（定期停車、または抑止の予約がある駅）の番線に入ったら、駅の中心 km で止まり、`dwelling` になる。止まる駅でなければそのまま通過する。

**信号待ち（`signal`）**
- 次のリソースが空いたら、`RESTART_LOSS_SEC`（45秒）待ってから `running` に戻る（止まったあとの再加速の分）。待っている間に再びふさがったら、タイマーをリセットする。

**停車（`dwelling`）** — 次の条件をすべて満たすと発車できる。
- 定期停車の場合: 到着から `MIN_DWELL_SEC`（150秒）以上たっている、かつ現在時刻が定刻の発車時刻以降（早発はしない）
- 運転停車の場合: 到着から `OP_STOP_MIN_SEC`（90秒）以上たっている
- 抑止されていない（`held = false`）
- 次の区間の最初のブロックが空いている

**終点到着**
- 終点の番線に入ったら到着時刻を記録し、`finalDelaySec = 到着時刻 − 定刻到着時刻` とする。
- `turnaround` になり、`TURNAROUND_SEC` たったらホームを解放して `done` にする。

### 3.6 速度

- 最高速度 `MAX_SPEED_KMH = 285`（全種別共通。種別ごとの速さの違いは停車駅の数から生まれる）
- ダイヤ上の速度 `SCHED_SPEED_KMH = MAX_SPEED_KMH × SCHED_SPEED_RATIO`（0.88）。この差が余裕時分になり、遅れた列車はこの分だけ取り戻せる。
- **速度の決め方:** そのときの遅延が0秒より大きければ `MAX_SPEED_KMH`、0秒以下なら `SCHED_SPEED_KMH`。区間に速度規制（M4）があれば、規制値との小さい方を使う。

### 3.7 進路（番線の選択）

- 列車ごと・駅ごとに、どの番線に入るかを持つ（`routes[stationId] = trackId`）。
- 列車の先頭が駅の上端から `ROUTE_LOCK_KM`（2.0 km）以内に入ったとき、進路が確定する。それまではプレイヤーが変更できる。
- 確定の時点でプレイヤーが指定していなければ、**自動ルール**で決める。

**自動ルール（ベースラインでもこのまま使う。わざと単純にしている）**

| 列車の状況 | 選ぶ番線 |
|---|---|
| その駅に定期停車する | ホームがある番線のうち、本線以外 → 本線の順で、空いている最初の番線。全部ふさがっていれば、その順の最初の番線（空くまで手前で待つ） |
| 抑止予約がある（運転停車） | 本線以外 → 本線の順で、空いている最初の番線。ホームの有無は問わない。全部ふさがっていれば最初の番線 |
| 通過する | 本線が空いていれば本線。ふさがっていれば空いている他の番線。全部ふさがっていれば本線 |
| 終点 | 番線番号の小さい順で空いている番線。全部ふさがっていれば、折り返しの残り時間が最も短い番線 |

**有効な番線:** 定期停車する駅（終点を含む）では、ホームのある番線しか選べない。それ以外の駅では、どの番線も選べる。

### 3.8 ダイヤ（定刻）の作り方

列車ごとに「入線点での定刻 `schedEntrySec`」と「停車駅のリスト」を与え、定刻表は自動で計算する。

- 区間の所要時間 = 距離 ÷ `SCHED_SPEED_KMH`
- 停車駅: 定刻到着 = 駅中心に着く時刻、定刻発車 = 定刻到着 + `SCHED_DWELL_SEC`（210秒）
- 通過駅: 定刻通過 = 駅中心を通る時刻
- 終点: 定刻到着のみ

`MIN_DWELL_SEC`（150秒）と `SCHED_DWELL_SEC`（210秒）には、どちらも加減速のロス（90秒相当）を含める。停車1回につき通過列車より約2.5分以上遅くなるので、各停が速達の邪魔になる。

### 3.9 遅延の計算（画面表示用）

`delaySec(train, now)` は状態によって次のように計算する。

| 状態 | 計算式 |
|---|---|
| `queued` | `now − schedEntrySec` |
| `running` / `signal` | `now − 定刻位置時刻(km)`。定刻位置時刻は、直前の時刻点（入線点・駅の発車/通過時刻）からダイヤ上の速度で線形補間して求める |
| `dwelling`（定期停車） | `max(now, 到着時刻 + MIN_DWELL_SEC) − 定刻発車` |
| `dwelling`（運転停車） | `max(now, 到着時刻 + OP_STOP_MIN_SEC) − 定刻通過` |
| `turnaround` / `done` | `finalDelaySec` |

- 表示は `floor(delaySec / 60)` 分。1分以上なら赤字で `+N`、1分未満なら何も表示しない（選択中の詳細パネルには「定刻」と表示する）。
- **定時率** = 終点到着時点の遅延が60秒未満の列車の割合。

### 3.10 プレイヤーのコマンド

コマンドはデータとして `step()` に渡す（リプレイやテストでも使えるように）。

```js
{ type: 'setRoute', trainId, stationId, trackId } // 進路の指定。確定済み・無効な番線なら無視する
{ type: 'hold',     trainId }                     // 抑止
{ type: 'release',  trainId }                     // 抑止の解除
```

**`hold` の動作**
- 列車が駅の番線にいる場合（停車中・通過中を問わない）: `held = true`。通過中だった場合は駅中心で止まり、運転停車として `dwelling` になる。
- 列車が区間を走っている場合: 次の駅に抑止を予約する（`holdAt = 次の駅ID`）。その駅の番線に入ると駅中心で止まり、`held = true` になる。進路が未確定なら、確定時に §3.7 の「抑止予約がある」ルールを使う。
- 終点に向かっている列車・`queued` の列車には効かない（無視する）。
- 本線で抑止すると後続がつかえるが、それはプレイヤーの判断として認める。

**`release` の動作**
- `held = false`、`holdAt = null` にする。発車条件（§3.5）を満たせば発車する。

### 3.11 ステージの終了

- 全列車が `turnaround` または `done` になったら終了する。
- ゲーム内時刻がステージの `maxDurationSec` を超えたら打ち切る。終点に着いていない列車は `finalDelaySec = その時点の delaySec + UNFINISHED_PENALTY_SEC`（600秒）とする。

### 3.12 定数一覧（`src/config.js`）

| 定数 | 初期値 | 意味 |
|---|---|---|
| `DT_SEC` | 1 | 1ティックの長さ（秒） |
| `GAME_SEC_PER_REAL_SEC` | 20 | 等速時の時間の速さ |
| `SPEED_MULTIPLIERS` | [1, 2, 4] | 倍速ボタンの倍率 |
| `MAX_SPEED_KMH` | 285 | 最高速度 |
| `SCHED_SPEED_RATIO` | 0.88 | ダイヤ上の速度の比率 |
| `BLOCK_KM` | 3.0 | ブロックの基準の長さ |
| `STATION_HALF_KM` | 0.5 | 駅の半分の長さ |
| `ROUTE_LOCK_KM` | 2.0 | 進路が確定する距離 |
| `MIN_DWELL_SEC` | 150 | 最短停車時間（加減速ロスを含む） |
| `SCHED_DWELL_SEC` | 210 | ダイヤ上の停車時間（同上） |
| `OP_STOP_MIN_SEC` | 90 | 運転停車の最短時間 |
| `RESTART_LOSS_SEC` | 45 | 信号待ちからの再発車ロス |
| `UNFINISHED_PENALTY_SEC` | 600 | 打ち切り時に未到着の列車へ加える遅延 |
| `PAX` | 速達 1300 / 快速 1000 / 各停 700 | 種別ごとの乗客数 |

## 4. ステージ

### 4.1 データ形式（`src/stages/*.js`）

```js
export default {
  id: 'stage1',
  title: 'はじめての待避',
  startClockSec: 10 * 3600,   // 盤面の開始時刻（ゲーム内）
  warmupSec: 0,               // 操作開始前に自動運転で進める秒数
  maxDurationSec: 3600,       // 打ち切りまでの秒数（startClockSec から数える）
  entryKm: -10,
  entryLabel: '東京方面',
  stations: [
    { id: 'aoba', name: '青葉', km: 0, tracks: [
      { id: 'aoba-1', label: '1番線', isMain: true,  hasPlatform: false },
      { id: 'aoba-2', label: '2番線', isMain: false, hasPlatform: true  },
    ]},
    // ...
    { id: 'minato', name: '港', km: 40, isTerminal: true, turnaroundSec: 300, tracks: [ /* 全番線 hasPlatform: true */ ] },
  ],
  trains: [
    // entrySec は実際に入線点へ現れる時刻（盤面の時刻）。schedEntrySec = entrySec − initialDelaySec
    { id: 'L801', type: 'L', number: 801, entrySec: 10*3600 + 0,  initialDelaySec: 8*60, stops: ['aoba', 'shirasagi'] },
  ],
  stars: { two: 0.15, three: 0.30 }, // ベースラインからの改善率のしきい値
  tutorial: [ /* §6.6 */ ],
};
```

- 種別: `S` = 速達（黄）、`R` = 快速（赤）、`L` = 各停（青）
- `stops` に終点は書かない（全列車が終点で止まる）
- `warmupSec > 0` の場合は、操作開始前にその秒数だけ自動運転で進め、線路上がすでに混んだ状態から始める。ベースラインも同じ状態から計算する。

### 4.2 ステージ1「はじめての待避」（チュートリアル）

**ねらい:** 遅れた各停を待避駅で抑止し、後ろの速達2本を先に通す。この操作1つで成績が大きく良くなることを体験させる。

| 駅 | km | 番線 |
|---|---|---|
| 青葉 | 0 | 1番線（本線・ホームなし）/ 2番線（副本線・ホームあり） |
| 白鷺 | 20 | 1番線（本線・ホームなし）/ 2番線（副本線・ホームあり） |
| 港（終点） | 40 | 1〜3番線（すべてホームあり）。折り返し 300秒 |

入線点: -10 km。

| 列車 | 種別 | 入線（実際） | 初期遅延 | 停車駅 |
|---|---|---|---|---|
| L801 | 各停 | 10:00:00 | +8分 | 青葉、白鷺 |
| S1 | 速達 | 10:01:30 | 0 | なし |
| S3 | 速達 | 10:04:00 | 0 | なし |

**調整の条件（テストで確認する）**
- ベースライン（操作なし）では、S1・S3 の両方が L801 につかえて、終点到着時の遅延がそれぞれ3分以上になる。
- 「L801 が白鷺に止まったら `hold` し、S3 が白鷺を通過したら `release` する」という操作で、遅延損失がベースラインより30%以上減る。
- 上の2つを満たすまで、入線時刻や初期遅延を調整する。

### 4.3 ステージ2「湖東〜浪速 107km」

**ねらい:** 元ネタの画面のように、終点の手前まで列車が数珠つなぎになっている状況を再現する。待避と発車順の入れ替えで、乗客の多い列車の遅れを減らす。

| 駅 | km | 番線 | 停車する種別 |
|---|---|---|---|
| 湖東 | 0 | 11番線（本線・ホームなし）/ 12番線（副本線・ホームあり）/ 13番線（副本線・ホームあり） | 快速、各停 |

## 5. スコア

- **遅延損失**[人分] = Σ `PAX[type] × max(0, finalDelaySec) / 60`
- **ベースライン**: ステージ開始時に、同じステージをコマンドなしで画面を使わずに最後まで計算する（決定的なので毎回同じ値になる）。
- **改善率** = `1 − プレイヤーの遅延損失 / ベースラインの遅延損失`（ベースラインが0なら0とする）
- **星**: クリアで★1、改善率が `stars.two` 以上で★2、`stars.three` 以上で★3
- 各ステージの最高の星の数を `localStorage` に保存する。読み書きは必ず `try/catch` で囲み、失敗しても遊べるようにする。

## 6. 画面とUI

### 6.1 全体

- **スマホの縦画面を優先する**（基準は 375×812）。PC では中央に最大幅 480px の列として表示する。
- 画面の構成（上から順に）:
  1. **HUD**（上部に固定）: ステージ名、時刻 `HH:MM`、一時停止・1x・2x・4x のボタン、現在の総遅延（全列車の表示遅延の合計[分]）
  2. **盤面**（縦にスクロールできる）: 路線と列車
  3. **詳細パネル**（下部に固定。列車を選んでいるときだけ表示）
- 描画には SVG を使う。

### 6.2 盤面のレイアウト

- 上が入線点（上流）、下が終点。列車は上から下へ進む。
- 縦方向の位置: 区間は km に比例させ、駅は固定の高さ `STATION_BOX_PX`（72px）の箱にする。
  - `pxPerKm` は「盤面全体が画面の高さに収まる値」とし、ただし1ブロックが18px未満にならないようにする。収まらないときは縦スクロールにする。
  - 区間にいる列車は、その区間の範囲内で km に比例した位置に置く。駅にいる列車は、駅の箱の中の番線の列に置く。
- 路線は、画面中央の縦の破線で描く（元ネタの青い破線のような雰囲気。色は独自にする）。
- 駅の箱: 上に駅名、下に番線ラベル。番線は縦の列として並べ、本線の列を路線と同じ x 位置（中央）に置き、副本線を左右に交互に並べる。駅の入口と出口では、路線から各番線へ斜めの線で分岐・合流させる。
- 入線点の上に `entryLabel` を表示し、`queued` の列車があれば「待機 N本」を表示する。

### 6.3 列車の表示

- 下向きの五角形（ホームベース形）、16×22px 程度。色は種別ごと。
- 左側に「種別名＋番号」（例: 「速達 38」）、下に赤字で遅延（例: `+67`）。
- 遅延の表示が1分減ったときは、緑の `−1` を一瞬浮かべる（遅れを取り戻した手応えのため）。
- 抑止中の列車には「抑」の赤いバッジを付ける。抑止予約がある列車には、点線の「抑」を付ける。
- 選択中の列車は太い枠で囲む。
- タップ判定: 列車の中心から24px以内で最も近い列車を選ぶ（列車が小さく、間隔が狭いため）。

### 6.4 ポイント（進路切り替え）— 中心となる操作

- 終点以外の各駅の入口に、ポイントのアイコン（タップ領域44×44px以上）を置く。
- **対象列車**: その駅に向かっている列車のうち、進路が未確定で最も駅に近い列車。対象列車があれば、その列車に脈打つ輪を付け、選ばれている番線までの経路を色付きの線で表示する。
- ポイントをタップするたびに、対象列車の進路を有効な番線の中で順に切り替える（`setRoute` コマンドを送る）。
- 終点にもポイントを置き、同じ操作で入る番線を選べるようにする。
- 進路が確定した列車の経路は、細い線で表示を続ける（どこへ入るか分かるように）。

### 6.5 詳細パネル

列車を選んでいるときに表示する。

- 種別・番号・乗客数・現在の遅延（「+12分」または「定刻」）・次の駅・次の駅の進路（確定済みなら鍵アイコン）
- ボタン:
  - 「抑止」/「抑止解除」: 状態に合わせて切り替える。区間を走っている場合は「次駅で抑止」と表示する
  - 「閉じる」
- 列車が `done` になったら、パネルを自動で閉じる。

### 6.6 チュートリアル（ステージ1のみ）

- 吹き出しを順番に出す。各ステップは「表示する条件」と「次へ進む条件」を持つ。条件が満たされるまで、ゲームを自動で一時停止して待つ。
  1. 「青い列車は各停。8分遅れています。各停は全部の駅に止まるので、後ろの速達がつかえてしまいます」→ タップで次へ
  2. （L801 が白鷺に着いたとき）「白鷺駅で各停を抑止して、速達を先に通しましょう。各停をタップして『抑止』」→ `hold` されたら次へ
  3. （S3 が白鷺を通過したとき）「速達が通過しました。各停の『抑止解除』で発車させましょう」→ `release` されたら次へ
  4. 「ポイントをタップすると、列車が入る番線を変えられます」→ タップで閉じる

### 6.7 その他の画面

- **タイトル / ステージ選択**: ゲーム名、ステージ一覧（最高の星の数）、遊び方（3行程度）
- **結果画面**: 遅延損失（自分とベースライン）、改善率、星、定時率、列車ごとの表（列車・終点到着遅延・ベースラインとの差）、「もう一度」「次のステージ」「ステージ選択」
- **キーボード（PC）**: Space = 一時停止の切り替え、1/2/3 = 倍速、Esc = 選択解除

### 6.8 見た目

- 色は `:root` の CSS 変数にまとめる。
  - 速達 `#F2C200`、快速 `#E5393B`、各停 `#1F7AE0`、遅延の文字 `#D32F2F`、回復 `#2E9E4F`
  - 路線・駅の枠: `#2C4BA8` 系
  - ヘッダーは独自の紺（`#1B2A49`）にする。実在の鉄道会社のコーポレートカラーに寄せない
- 背景は明るいグレー。ダークモードは対応しない（試作のため）。
- フォントは `system-ui, "Hiragino Sans", "Noto Sans JP", sans-serif`。

### M4: 拡張（M3 を遊んでから、やるかどうか決める）
- **指令カード**（ステージごとに使える回数を決める）

## 11. 今後決めること（試作のあとで）

- ゲームの正式名称（『定時に戻せ！』は仮）
