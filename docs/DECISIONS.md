# 実装中に決めたこと

SPEC.md に書かれていない細部や、仕様と違う扱いにしたことを1行ずつ残す。

## M1（シミュレーション本体）

- `npm test` は `node --test`（引数なし）にした。SPEC の `node --test tests/` は Node 21 以降で引数が glob 扱いになり、ディレクトリ指定が失敗する。引数なしなら Node 20 / 22 のどちらでも `tests/*.test.js` を拾う。SPEC §7 の該当行も直した。
- `step()` は state を直接書き換えて返す（毎フレーム最大400回呼ぶので、コピーしない）。
- ティック内の判断（発車可否・信号待ちタイマー・進路確定）はティック開始時刻 `state.timeSec` で行う。到着時刻だけは、そのティックの終わり（`timeSec + DT_SEC`）を記録する。
- 終点の「到着」は、番線に入った時ではなく駅中心に着いた時とする（定刻到着も駅中心の時刻なので揃える）。
- 進路確定の判定は、そのティックの移動前の km で行う（確定が最大1ティック＝約0.07km 遅れる。誤差として許容）。
- 定刻表と遅延の時刻は丸めず実数の秒のまま持つ。整数なのはゲーム内時計だけ。
- 駅中心を過ぎて出ていく途中の列車への `hold` は、「区間を走行中」と同じく次の駅への予約にする（次が終点なら無視）。
- `setRoute` は `queued` の列車にも効く（進路は未確定なので）。`hold` / `release` は `queued` には効かない。
- `hold` を `queued` の列車に送っても無視されるので、入線後に送ること（チュートリアルやテストで注意）。
- 終点の自動ルールで全番線がふさがっているとき、まだ到着していない列車が入っている番線は「折り返し時間まるごと残っている」とみなす。残り時間が同じなら定義順（番線番号の小さい方）。
- 同じ km の列車の処理順は「本線にいる列車 → 列車ID順」。
- 打ち切りは `timeSec − startClockSec > maxDurationSec`（超えたら）で判定する。
- ステージ定義で `entrySec < startClockSec` の列車は例外にする。許すと、開始と同時に押し込まれてその分が余計な遅延になる。
- ブロック分割は `ceil(長さ/BLOCK_KM − 1e-9)`（浮動小数の誤差でブロックが1個増えるのを防ぐ）。
- `score.js`（遅延損失・改善率・星の数・定時率）は `runHeadless` が損失を返すため M1 で先に作った。`starCount` の「クリア」判定は M3 で決める。
- ステージ2の駅IDは `kodo`(湖東) / `konan`(湖南) / `koto`(古都) / `naniwa`(浪速)、番線IDは `<駅ID>-<番号>`。停車駅は 速達=古都 / 快速=湖東・古都 / 各停=湖東・湖南・古都（SPEC §4.3 の表どおり）。
- ステージ2の `stars` は SPEC に値がないので、仮に two 0.10 / three 0.20 とした。M3 で遊んでから決める。
- テストに `tests/helpers.js`（小さなステージを作る補助）を足した。SPEC §7 のファイル構成にない追加。

## M1 で見つかった、仕様の調整条件（§4.2 / §4.3）との食い違い

- **[M3 で解決] ステージ1が §4.2 の条件1を満たせなかった → `RESTART_LOSS_SEC` を 45 → 120 に変更し、S1・S3 の入線時刻を調整した。** 当初の SPEC の値では、ベースラインの終点遅延は L801 6.2分・S1 0.0分・S3 0.0分（損失 4368 人分）で、入線時刻と L801 の初期遅延だけを動かした約3.4万通りの探索でも S1・S3 の遅延の最大は約39秒だった。原因の見立て: 自動ルールが停車列車を先に副本線へ入れるので速達は本線を素通りでき、全列車の最高速度も同じなので、つかえるのは発車直後の1ブロック＋再発車ロスだけ。SPEC §0.5 が許す定数の調整として `RESTART_LOSS_SEC` を振り（ブロック基準3/5km × 再発車ロス45/90/120/180秒）、3km のまま 120 秒が最小の変更で両条件を満たせた（90秒以下は満たせない）。L801 は SPEC どおり（10:00:00・+8分）に固定し、S1 を 10:01:30 → 10:02:30、S3 を 10:04:00 → 10:05:15 にした。結果: ベースラインの終点遅延は L801 4.6分・S1 3.7分・S3 3.5分（損失 12,476）、「白鷺で L801 を `hold` し、S3 が白鷺を出たら `release`」で S1 1.1分・S3 1.0分・L801 7.9分、損失 8,231、改善率 34.0%。SPEC §3.5・§3.12・§4.2 の該当箇所も直した。120秒は、285km/h の列車が信号で止まってから巡航速度に戻るまでの損失として無理のない値。ステージ2のベースラインも変わった（損失 802,575 → 895,738、浪速手前で最大6本が `signal`）。この変更は仕様の持ち主が取り消してよい（その場合 T8 は満たせない）。
- **[T9 の想定どおり] ステージ2は条件1を満たすが、条件2は満たさない。** `RESTART_LOSS_SEC=120` でのベースライン損失は 895,738 人分。浪速の手前で最大6本が同時に `signal` になる（19:05）ので条件1は OK。条件2（全ての各停を湖南で `hold` し、後ろの速達が通ったら `release`）は、後続の速達を2本通した場合で損失 888,688（0.8%改善）、3本で 885,468（1.1%改善）、0〜1本は0%で、10%に届かない。浪速（4番線×折り返し900秒）の処理能力で遅れの総量が決まっていて、順番の入れ替えでは動かしにくい。SPEC §9 の補足（運休・折返し短縮を最優先）どおり。T9 は `skip` にして、この数値を理由に書いた。

## M2（盤面の描画・操作なし）

- 列車のラベルは、区間では「左に種別と番号・右に赤字の遅延」の1行ずつ、駅の番線では「列車の下に中央揃えで種別と番号、その下に遅延」にした（SPEC §6.3 は「左に種別と番号、その下に遅延」）。ブロックが18pxの間隔で並ぶと2行では隣の列車の名前に被り、終点の4番線は横に並んで被ったため。
- 番線の列の間隔は56px（`TRACK_GAP_PX`）、駅の入口・出口で斜めに分岐・合流する範囲は駅の長さの25%（`BRANCH_RATIO`）。SPEC に数値の指定がないので、ラベルが隣の番線に被らない最小の広さで決めた。
- 駅の箱は、番線の km の範囲（駅の長さ1km）を箱の高さ72px全体に対応させる。区間のブロックから番線に入る境目で、列車の座標が途切れずつながる。名前は左上、番線ラベルは下に置いた。
- 盤面の上端に入線点のラベル（「▼ 東京方面」「待機 N本」）の場所を76px取った。入線点にいる列車の本体（先頭から上に22px）と文字が重ならないため。
- ステージ2は盤面が約1140pxになり縦スクロールになる（1ブロック18px以上のため）。浪速の手前の数珠つなぎは、下へスクロールして見る。自動スクロールはしない。ステージ1は 375×812 で収まる。
- ブロックの境目に薄い短い目印を描いた（SPEC にない追加）。詰まりがブロック単位で見えるため。
- 総遅延は、全列車（入線待ち・終点に着いた列車を含む）の表示遅延（分。1分未満は0）の合計。
- 「−1」の演出は、表示遅延が1分以上から1分減ったときに出し、アニメーションの終了か1.5秒で消す（画面が非表示だと `animationend` が来ないため、時間でも消す）。
- ゲームループは、実経過時間 × 倍率 × 20 を端数ごと持ち越して配分し、1フレーム400ティックを超えた分だけ切り捨てる（`src/loop.js`。SPEC §3.1 のとおり。フレーム間隔そのものは切り捨てない）。起動時に1回、最初のフレームを待たずに描く。
- M2 はステージ2を開く。`?stage=stage1` でステージ1も開ける（タイトル・ステージ選択は M3）。
- 抑止のバッジ・列車の選択・ポイント・詳細パネルは M3（M2 は操作なし）。
- ブラウザでの確認の注意: Claude のブラウザペインが非表示のときは `requestAnimationFrame` が止まる。確認では `window.requestAnimationFrame` を `setTimeout` に差し替え、`main.js` を `?クエリ` 付きで1回だけ読み込んだ（同じページに何度も重ねると HUD と盤面が混ざる）。`game.advance(秒)` で時刻を進められる。

## M3（操作・スコア・画面遷移）

- 操作（`setRoute` / `hold` / `release`）は、一時停止中でもすぐ効くよう、次の `step()` を待たずに `applyCommand` で適用する（`step` が最初にやることと同じ処理なので結果は変わらない）。適用できた操作は `session.log` に `{ t, cmd }` で残す（リプレイやテストで再現できる）。
- 星: 「クリア」は、ゲームが終わったこと（全列車が終点に着いた `completed`、または打ち切りの `timeout`）とした。打ち切りでも★1以上になる。★2・★3は改善率のしきい値（`stars.two` / `stars.three`）で決まる。何も操作しなければ改善率0で★1。
- ステージ2の星のしきい値は、SPEC に値がなく、仮のまま（two 0.10 / three 0.20）。条件2を満たせない（T9 は `skip`）ので、いまのルールでは★2以上を取れる操作が見つかっていない。M4 の指令カードを入れるか、しきい値を下げるかは、遊んでから決める。
- ポイントのアイコンは、各駅の箱の上端の、路線から右へ50pxの位置に置く（タップ領域 44×44px）。路線上の列車のタップ判定（中心から24px）と重ならず、駅に入る列車の文字とも被らない。対象列車は SPEC のとおり「進路が未確定で最も駅に近い列車」なので、遠くにいる列車が対象になることもある（輪とオレンジの経路で分かる）。
- ポイントをタップすると、対象列車の番線を「今選ばれている（または自動ルールでいま決まる）番線」の次の有効な番線へ切り替える。有効な番線が1本だけの駅（定期停車するホームが1本）では何も変わらない。
- 空いている所をタップしても、列車の選択は解除しない（SPEC の解除手段は「閉じる」と Esc のみ）。
- 詳細パネルは盤面に重ねて表示し、盤面の大きさは変えない（変えると、列車を選ぶたびに盤面の縮尺が変わってしまう）。パネルが開いている間は、盤面の下に余白を足して、隠れた部分もスクロールで見られるようにした。
- 抑止ボタンの表示は `holdAction`（`src/sim/commands.js`）で決める: 「抑止」（その場で効く）/「次駅で抑止」（区間を走行中。次の駅に予約）/「抑止解除」（抑止中または予約中）/ 押せない（終点へ向かう列車・終点・入線待ち）。`hold` の判断と同じ関数（`holdPlan`）を使うので、ボタンの表示と実際の動作はずれない。
- チュートリアルの吹き出しは、列車を隠さないよう盤面の下側に置き、パネルが開いているときはその上に出す。1つ目の吹き出しは、L801 が入線して盤面に見えてから出す。文言は「8分遅れ」を「約8分遅れ」にした（入線した直後の1ティックで 480秒が 479.9秒になり、`floor` で +7 と表示されるため）。
- チュートリアルの「S3 が白鷺を通過した」は、S3 が白鷺の番線を出て次の区間に入った（`nextStation >= 2`）こととした。駅中心を過ぎただけで解除すると、L801 が先に次のブロックへ入って S3 がつかえるため。T8 のテストも同じ条件。
- ステージ選択へ戻るボタン（HUD 左端の「‹」）を足した（SPEC にない追加）。確認ダイアログを出す。
- URL の `?stage=stage1` でタイトルを飛ばして始められる機能は、動作確認用に残した。
- 結果画面の「操作なしとの差」は、自分の終点到着遅延 − ベースラインの終点到着遅延（マイナスが良い）。±6秒未満は色を付けない。
- 星の保存キーは `rbot.stars.v1`。値が壊れていたり範囲外（0〜3以外）だったりしたら捨てる。`localStorage` へのアクセス自体が例外になる環境でも、タイトル・プレイ・結果まで動く（ブラウザで確認済み）。
- `RESTART_LOSS_SEC=120` にしたため、ステージ2は全体に重くなった（例: 各停844 の終点到着遅延は初期遅延 +73分に対して +83.6分）。「遅れを取り戻す」感触が弱いかもしれない。遊んでから、ステージ2の初期遅延や折り返し時間で調整する。

## M4（指令カード・イベント）

- 範囲: 指令カード（運休・折返し短縮）とイベント（速度規制・車両点検による臨時停車）を実装した。上り方向とステージ3「全線」は入れていない（SPEC §11 が「扱うかどうか」自体を未決としていて、列車の向きの扱いを作り直す大きな設計判断になるため）。
- 動機: M3 のステージ2では、各停を抑止する操作で最良でも 2.4% しか改善できず、★2以上を取れなかった（遅れの総量が終点の浪速の処理能力で決まる）。SPEC §9 の補足どおり、運休と折返し短縮を先に入れた。
- 運休（`{ type: 'cancel', trainId }`）: 次に停車する駅（定期停車・運転停車・終点）の駅中心に着いたところで、その列車を盤面から消す。停車中の列車にはその場で効く。もう停車しない列車は終点で折り返さずに消えるので、浪速のホームを折り返しの900秒ぶん占有しない。遅延損失は SPEC どおり「乗客数 × 60分」（終点到着遅延を3600秒として数える。`CANCEL_DELAY_SEC`）。入線待ち・終点に着いた列車・予約済みの列車には使えない（カードは減らない）。
- 運休は、遅れが60分に満たない列車に使うと、かえって損失が増える（SPEC どおりの設計）。ステージ2で確かめた: 運休を遅れの小さい列車（S104・S48）に使うと −3.7%。これが「どの列車に使うか」の判断の要素になる。
- 運休は取り消せないので、画面のボタンは2度押しにした（1回目で「もう一度タップで運休」に変わり、4秒以内に2回目を押したときだけ実行する）。
- 折返し短縮（`{ type: 'shortenTurnaround', trainId }`）: 終点で折り返し中の列車を選んで使い、その列車の折り返しを「到着から折り返し時間の半分がたった時刻」に終わらせる（`SHORTEN_TURNAROUND_RATIO=0.5`）。すでに半分を過ぎていれば、その場で終わる。1本につき1回。
- 速度規制: `{ type: 'speedLimit', label, fromKm, toKm, kmh, fromSec, toSec }`。ティックの頭の位置と時刻で判定し、走る速度を「通常の速度と規制値の小さい方」にする（SPEC §3.6 のとおり）。定刻表には織り込まないので、規制中は遅れる。規制区間を出たあとは、遅れた列車が最高速度で取り戻す。画面の帯は、始まる10分前から点線で予告し、規制中は実線にする。
- 車両点検: `{ type: 'inspection', trainId, stationId, durationSec }`（1本につき1回）。その列車が、その駅で駅中心に止まり、`durationSec` たつまで出られない（`release` でも解除できない）。自動ルールでは運転停車と同じく本線以外の番線を選ぶ。その駅に定期停車する列車は、停車時間が最短停車と点検の長い方になる。予定は最初から画面に出す（列車に「点」のバッジ、パネルに注記）。
- 出来事は `state.notices`（`{ t, kind, ... }`）に構造化データで積み、画面（`src/render/notices.js`）が文面にして画面上部に出す。プレイ開始前（warmup 中）の出来事は知らせない。
- ステージ2: カードは運休2・折返し短縮3。イベントは、湖南〜古都の強風による速度規制（170km/h、18:50〜19:25）と、快速718の湖南での車両点検（6分）。ステージ1にはカードもイベントもない（チュートリアルの数値は変わらない）。
- ステージ2の測定（`RESTART_LOSS_SEC=120`、イベントあり、ベースライン損失 900,513）: 折返し短縮のみ（3回、最初に着いた列車から）6.2%、運休のみ（L844・R660）16.0%、運休（L844・R660）＋折返し短縮3回 21.3%、運休2本の最良の組み合わせ（L844・S38）＋折返し短縮3回 23.3%。星のしきい値は two 0.10 / three 0.18（人の操作は最良より少し劣る前提）。
- ステージ2のイベント（速度規制・点検）は、ベースライン損失をほとんど動かさない（895,738 → 900,513、+0.5%）。遅れの総量が終点の処理能力で決まるため。イベントは、状況の変化として画面に出て、運休を使う判断の材料になる程度の役割。
- T9（各停を湖南で抑止する操作で10%以上）は、カードなしの条件のまま `skip` にしてある。代わりに、カードを使えば★3に届くこと、折返し短縮だけでは★2に届かないこと、遅れの小さい列車の運休は逆効果なことを `tests/stages.test.js` で確認している。
- `runHeadless` の操作の予定の `command` は、コマンドそのものに加えて、state からコマンドを作る関数でも書けるようにした（折返し短縮は「そのとき終点にいる列車」を選ぶ必要があるため）。
- HUD に、指令カードの残り回数の行を足した（カードのあるステージだけ）。結果画面では、運休の列車を「運休（60分扱い）」と表示する。
